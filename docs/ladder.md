# ラダー側の対応（叩き台）

アプリの指令送信方式 B（[design.md](design.md)）に合わせたラダーの例。**既存のラダー構成に合わせて設計し直すこと。** デバイス番号はすべて仮。

## デバイス割り当て（例）

| 用途 | 物理入力 | PC 指令 | 要求（合成） |
|---|---|---|---|
| ON | X0 | M100 | M200 |
| OFF | X1 | M101 | M201 |
| 停止要求 | X2 | M102 | M202 |

| デバイス | 用途 |
|---|---|
| M300 | 運転状態（自己保持） |
| Y0 | 出力 |

## 回路例

```text
 (1) 物理入力と PC 指令の OR
       X0                                          M200
 ──┬──┤ ├──┬──────────────────────────────────────( )──   ON 要求
   │  M100 │
   └──┤ ├──┘
       X1                                          M201
 ──┬──┤ ├──┬──────────────────────────────────────( )──   OFF 要求
   │  M101 │
   └──┤ ├──┘
       X2                                          M202
 ──┬──┤ ├──┬──────────────────────────────────────( )──   停止要求
   │  M102 │
   └──┤ ├──┘

 (2) 自己保持（OFF・停止要求を優先）
      M200        M201     M202                    M300
 ──┬──┤ ├──┬──────┤/├──────┤/├────────────────────( )──
   │  M300 │
   └──┤ ├──┘

 (3) 出力
      M300                                          Y0
 ─────┤ ├──────────────────────────────────────────( )──

 (4) PC 指令の受付完了（プログラムの最後に置く）
      M100
 ─────┤ ├──────────────────────────────────[ RST M100 ]──
      M101
 ─────┤ ├──────────────────────────────────[ RST M101 ]──
      M102
 ─────┤ ├──────────────────────────────────[ RST M102 ]──
```

## ポイント

- **(4) の RST がアプリの受付確認になる。** アプリは M100 を ON にした後、PLC が OFF に戻すのを待つ。RST がないと、アプリは「PLC が受け付けなかった」と判断して M100 を OFF に戻す（NOT_ACCEPTED）。
- SLMP による書き込みは END 処理で反映されるため、PC 指令の M は次のスキャンで (1) に取り込まれ、同じスキャンの最後の (4) で OFF に戻る。つまり **PC 指令は 1 スキャンだけ ON になる**。このため (2) のような自己保持や SET / RST で状態を保持する必要がある。
- (4) は必ず (1) より後に置く。前に置くと、(1) で M100 を見る前に OFF になる。
- (2) では OFF 要求と停止要求が ON 要求より優先される（同時に来たら止まる）。
- 同じボタンを続けて押しても、毎回 1 スキャン分のパルスになるので正常に動作する。
- PC 指令は 1 スキャンで消えるため、LAN が切れても M が ON のまま残ることはない。
- X1・X2 を b 接点（NC）で配線する場合は、接点の向きを実際の配線に合わせる。
- **停止要求は非常停止ではない。** 非常停止は、このラダーとは独立した安全回路で実装すること。

## 動作確認の順番

1. まず (4) だけを追加し、アプリの「ON」で ACCEPTED になることを確認する（Y はつながない）。
2. (1)〜(3) を追加し、GX Works3 のデバイスモニタで M200・M300・Y0 の動きを確認する。
3. 物理入力（X0〜X2）とアプリの両方から操作できることを確認する。
4. ON と OFF の同時操作、連続操作、LAN ケーブルを抜いたときの動作を確認する。
