# 設計メモ

開発 INPUT 資料をもとにした叩き台の設計。**「暫定」と書いた項目は確定ではない**。実機検証や運用の検討を経て見直すこと。

## 構成

```text
gui.py (tkinter)                 画面。表示と入力だけを担当する
  │ submit()        ▲ 結果（キュー経由、after() で反映）
  ▼                 │
worker.py (TaskWorker)           通信専用スレッド。GUI をフリーズさせない
  │
  ▼
commands.py (CommandSender)      ON / OFF / 停止要求のハンドシェイク
  │
  ▼
plc/client.py (GuardedPlcClient) 許可したデバイス以外への書き込みを拒否する
  │
  ├─ plc/slmp.py (SlmpPlcClient)  実機: pymcprotocol で SLMP 3E フレーム（バイナリ）
  └─ plc/mock.py (MockPlcClient)  モック: ラダーの RST 動作を真似る
```

- GUI と通信処理は `PlcClient` インターフェースで分離している。実機・モックの切り替えは設定（`[connection] mock`、画面の [設定] のチェックボックス）だけで行う。
- pymcprotocol で FX5S に問題があった場合は、`plc/slmp.py` だけを差し替えればよい（自前で SLMP を実装する案も含む）。
- 設定は `config.toml` で行う（書式は `config.example.toml`）。接続先は画面からも変更でき、切り替えはワーカースレッドで行う（通信中のクライアントを別スレッドから閉じないため）。設定画面の接続確認は、今の接続とは別の一時的な接続で行う。

## 指令の送信方式

INPUT 資料 6 章の候補を比較し、叩き台では **方式 B** を採用した（暫定）。

| | A: PC からパルス | **B: PLC がリセット＋PC が確認** | C: D レジスタでコマンド番号 |
|---|---|---|---|
| 手順 | PC が M を ON → 一定時間後に PC が OFF | PC が M を ON → ラダーが処理後に RST → PC が OFF を確認 | PC が D に指令番号と連番を書く → ラダーが処理後に応答番号を返す |
| PLC が受け付けたか | 分からない | 分かる | 分かる |
| スキャンや通信遅延の影響 | パルス幅が短いと取りこぼし、長いと二重実行 | 受けない（ラダーが 1 回だけ処理する） | 受けない |
| 指令の残留 | PC が落ちると ON のまま残る | ラダーが必ず RST するので残らない | ラダーがクリアするので残らない |
| ラダーの変更量 | 少ない | 少ない（RST を足すだけ） | 多い（番号の判定や応答処理が必要） |
| 未受付で取り消す時の競合 | ― | わずかにある（下記） | 連番で判別できる |
| 拡張性 | 指令ごとに M が必要 | 指令ごとに M が必要 | D 1〜2 点で指令を増やせる |

方式 B を選んだ理由: 方式 A より確実で、方式 C よりラダーの変更が少なく、最初の動作確認に向いている。指令の種類が増える場合や、受付と完了を厳密に区別する必要が出た場合は方式 C へ移行する。PC 側の通信層は共通なので、`CommandSender` の差し替えで対応できる。

### 方式 B の動き（`commands.py`）

1. 未接続なら接続する。
2. 対象の M を読み、既に ON なら **BUSY**（前回の指令が PLC で未処理）として送信しない。
3. M を ON にする。
4. `ack_timeout_sec` まで `poll_interval_sec` ごとに M を読み、OFF に戻ったら **ACCEPTED**。
5. 時間内に戻らなければ PC が M を OFF に戻して取り消し、**NOT_ACCEPTED** とする。
6. 手順 3 より前の通信エラーは **ERROR**（未送信）。手順 3 より後の通信エラーは **ERROR** とし、「PLC で実行された可能性がある」と表示する。

**ACCEPTED は「PLC が指令を受け付けた」という意味であり、設備が動いたことは意味しない。** 設備の状態を表示したい場合は、Y や状態用の M を読む機能を別に追加する。

### 既知の制約

- 手順 5 で取り消す直前に PLC が処理していると、実際は実行されたのに NOT_ACCEPTED と表示されることがある。厳密に判別する必要があれば方式 C にする。
- 停止要求は ON / OFF の処理中でも受け付け、待ちの指令より先に送る。ただし処理中のハンドシェイクを中断しないため、最大で `ack_timeout_sec` だけ待つ（既定 1 秒）。
- ON / OFF は処理中に押しても受け付けない（キューに溜めない）。後から押した操作が遅れて実行されるのを防ぐため。

## ランプ（状態の読み出し）

メイン画面の「稼働中」「停止中」ランプは、設定した M を `[monitor] interval_sec`（既定 0.5 秒）ごとに読み出して表示する（`monitor.py`）。書き込みはしない。

- 読み出しはワーカーの「バックグラウンドタスク」として実行する。指令の送信より後回しにし、読み出し中でも ON / OFF を受け付ける。待ちは 1 件までなので、読み出しが溜まることはない。
- 読み出しに失敗したらランプを灰色（不明）にし、3 秒おきに再接続を試す。再接続中（最大でタイムアウト時間）は、押した指令がその分だけ待たされる。
- ランプは「PLC の M の状態」を表示するもので、設備の実際の状態を保証するものではない。M をどう作るかはラダー次第（[ladder.md](ladder.md)）。
- モック PLC は、ON を受け付けたら稼働中、OFF・停止要求を受け付けたら停止中に切り替わる（ladder.md の回路例と同じ動き）。

## 安全性（INPUT 資料 7 章との対応）

| 要件 | 叩き台での対応 |
|---|---|
| 停止要求を非常停止の代わりにしない | 非常停止は独立した安全回路で実装する（アプリの範囲外）。画面には注意書きを出さない |
| LAN 切断・アプリ停止時に危険にならない | 指令は 1 スキャンで消費されるパルスなので、切断しても M が ON のまま残らない。切断時に設備を止めるかどうかは未決定（下記） |
| 停止要求を ON より優先 | ラダーで停止・OFF を優先する（ladder.md）。PC 側でも停止要求を優先して送る |
| 不正なデバイスへの書き込みを防ぐ | 設定で指定できるのは M のみで、範囲もチェックする。さらに `GuardedPlcClient` が設定済みの 3 点以外への書き込みを拒否する |
| 送信成功と設備の動作を区別する | 結果は「PLC が受け付けた」までと表示し、設備の動作確認を促す |
| 実機出力をつながずに検証する | 設定でモック PLC を選べば実機なしで動かせる。実機の検証手順は README を参照 |

## 未決定事項と叩き台での暫定案

| 項目 | 叩き台の暫定案 | 備考・提案 |
|---|---|---|
| GUI: tkinter か PySide6 か | tkinter | 標準ライブラリだけで動き、EXE 化も軽い。画面が複雑になったら PySide6 を検討。GUI は `gui.py` に閉じているので差し替えやすい |
| IP アドレス等を GUI から設定するか | **決定**: [設定] 画面で IP アドレスとポート番号を変更し、保存前に接続確認できる。保存すると `config.toml` に書き込む | PLC 種別やタイムアウトなどは設定ファイルのみで変更する |
| M の割り当てを固定するか | 画面の [設定] → [リレー] タブと設定ファイルで変更可（M のみ・重複不可） | ラダーの割り当てと食い違うと誤動作につながる。本番で固定したい場合は、[リレー] タブを隠すか読み取り専用にする |
| 受付確認・完了確認の方法 | 方式 B（受付確認のみ） | 完了確認が必要なら方式 C か、状態用デバイスの読み取りを追加 |
| 通信切断時の PLC の動作 | 未実装 | 提案: PC が一定周期で D レジスタにハートビートを書き、ラダーが途絶を検知したら安全側に倒す |
| EXE の配布・インストール方式 | 未実装 | 提案: PyInstaller で単一フォルダ形式にし、`config.toml` を EXE と同じフォルダに置く |
| FX5S と pymcprotocol の互換性 | `plc_type = "L"` で試す | FX5 は Q/L 互換のデバイス指定を使うため。実機で `fx5s-probe` を使って確認する |
| ログ出力方式 | `logs/fx5s-commander.log`（1MB × 5 世代のローテーション） | 保存期間や出力先は運用に合わせて決める |
| アプリ名・リポジトリ名 | `fx5s-commander`（既存のリポジトリ名に合わせた） | INPUT 資料の候補は `plc-commander` |
